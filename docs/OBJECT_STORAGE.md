# 私有 R2 图片存储

现有 `/api/uploads` 接口支持最大 20 MiB 图片、512 KiB 分片、乱序/重复分片、断点续传和完整 SHA-256 校验。分片只暂存于 Node 本机；合并后校验真实图片类型、限制像素、剥离 EXIF/GPS，再将 JPEG 写入私有 R2。客户端接口和鉴权方式不变，无需分发 S3 密钥。

## 配置

将以下配置加入服务器 `server/.env`（权限 `600`，不提交 Git）：

```dotenv
IMAGE_STORAGE=r2
R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
R2_BUCKET=self
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_PREFIX=forspecialyou/uploads/
```

端点不包含桶名路径；SDK 区域固定为 `auto`。只需 S3 Access Key ID 和 Secret Access Key，代码不使用 Cloudflare 管理 API 令牌。凭证应限定为该桶的对象读写权限。保持桶私有，不启用公共开发 URL 或公开自定义域名；由 Node 访问 R2，无需浏览器直连 CORS。

启用前执行 `npm run storage:check -w server`。该命令仅使用合成图片，检查真实 R2 写入、读取、字节一致性、列举、删除及拒绝匿名访问，最终清理测试对象，不读取业务数据库记录。

## 读取、保留和失败重试

- 最终对象键为 `forspecialyou/uploads/<upload-id>/image.jpg`；元数据继续存在 `image_uploads`，不包含真实姓名或邮箱。R2 不替代 MySQL。
- `/api/uploads/:id/content` 校验有效会话、上传归属及过期时间后代理读取，响应禁止缓存。AI 读取也经过同一存储模块；AI 开关与 R2 独立，仍默认关闭。
- R2 写入失败返回 503，保留分片和未完成状态，可重试完成操作；不会把失败上传标记为完成。SDK 有连接/请求超时，最多尝试三次，不向客户端泄露签名、密钥或上游响应。
- 写入 R2 后保留受权限保护的本地最终副本与分片，以兼容配置回滚。读取优先 R2，仅当对象不存在时才回退旧本地图片；R2 故障返回 503。
- 未完成上传默认保留 24 小时，完成图片默认保留 30 天。管理员可在管理端 Storage 页面设置未完成分片的小时数，以及已完成文件的天数或永久保留；新设置默认只影响新上传和之后完成的文件，勾选“Apply to existing…”后才会从原始上传/完成时间重算现有未过期记录。缩短期限可能让文件立即进入清理范围，已过期记录不会被恢复。这是临时图片接口，永久模式也不应替代健康档案附件库。到期后接口立即拒绝读取，定时任务每小时清理；清理失败将在后续轮次重试。
- 删除时先删除远端和本地文件，成功后移除上传元数据；远端失败时保留元数据供重试。清理任务按本应用前缀分页扫描，并移除已过期或账号级联删除留下的孤立对象，不处理桶中其他前缀或非本应用图片键。

## 管理端保存时长

管理员登录后进入 `/storage`（侧栏 Storage）：

- **Unfinished uploads**：1–720 小时，从创建上传时计算，控制未完成分片的保留期限。
- **Completed files**：1–36500 天，从首次成功完成时计算；选择 **Keep permanently** 后不设自动到期时间，用户删除和账号删除仍会清理文件。
- 默认只应用于新上传和之后完成的文件。勾选 **Apply to existing active uploads and files** 会要求二次确认，按原始时间重算尚未过期的记录；已过期或删除的文件不恢复。
- 保存采用版本校验；其他管理员已修改时必须重新加载。设置存于 MySQL，重启后继续生效，修改写入审计记录。

已完成上传的本地副本及其原分片跟随完成文件的期限；只有仍未完成的上传使用小时设置。清理由应用每小时执行，不直接修改 Cloudflare 桶的生命周期规则；若桶已有自动删除最终对象的规则，其期限需要与这里的设置协调，永久模式应避免匹配这些对象的自动删除规则。

## 现有数据与范围

本次只接入已有分片上传产生的图片（例如餐食分析图片）。现有 `users.profile_image` 头像和业务 JSON 内嵌图片保持原格式，继续存于数据库；未自动将它们迁入 R2，也未修改原用户或健康记录。持久化附件和头像全面迁移需另行设计引用、归属、保留期、回显和迁移校验。

当前 API 服务仍在美国服务器 `154.40.41.179:3002`。用户创建的 R2 桶显示亚太地区；这不意味着文件在美国或中国大陆，也不提供中国大陆数据驻留保证。

## 回滚与凭证轮换

把 `IMAGE_STORAGE` 改为 `local` 后通过现有宝塔 Node 项目重启，可使用保留的本地副本。回滚时确认没有尚未写好本地副本的完成请求，再切换；不要删除桶或直接恢复旧数据库覆盖新数据。

本地模式不会执行 R2 清理；如果长期回滚，应单独清理到期远端对象，避免无限保留。

凭证若已出现在聊天或截图中，建议在控制台创建新凭证，替换服务器 `.env` 中两个 S3 字段，运行存储检查并重启后再撤销旧凭证。不要把管理 API 令牌填入 S3 Secret 字段。

测试：`npm test` 检查 S3 协议、分页、私有缓存、错误处理和重试；`npm run test:integration` 分别使用本地存储和本机 S3 模拟服务跑完整隔离 MySQL 集成测试，强制覆盖云凭证，避免测试误删真实对象。
